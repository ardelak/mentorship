Learning Objectives

So far, your programs have mostly worked with data stored on your own computer. This tutorial follows that data as it travels across the internet: a client asks a server for something, the server replies using HTTP, and your program turns the response into useful Python data.

By the end, you will be able to explain the request/response cycle, inspect GET and POST requests with curl, read JSON responses, call an API with Python's requests package, and build a small live-weather report with sensible error handling.

1 Foundation · Who talks to whom?

The Client-Server Model

A client starts a conversation. A server listens for requests and sends responses.

Think of a restaurant. You are the client, the kitchen is the server, and the waiter carries messages between them. On the web, your browser or Python script is the client; a remote program that provides data is the server; the network carries messages back and forth.

RestaurantWeb equivalentWhat it does
DinerClient: browser, app, Python scriptStarts a request for a resource or action.
OrderHTTP requestDescribes what the client wants and may include data.
KitchenServer programProcesses the request and decides how to respond.
Meal and billHTTP responseReturns a status, metadata, and possibly a body of data.
Request / response cycle
CLIENT                                      SERVER
  |                                           |
  |  1. Request: "weather for Tbilisi?" ----> |
  |                                           | process request
  |  2. Response: "200 OK" + weather data <-- |
  |                                           |
KEY IDEA

A server normally replies to a request; it does not spontaneously send a response to a client that has not asked. One server can handle requests from many clients.

2 Foundation · The shared communication rules

HTTP Requests and Responses

HTTP (HyperText Transfer Protocol) gives clients and servers a common structure for messages.

An HTTP request identifies a method and a resource. It can also include headers (metadata) and, for some methods, a body. The response includes a status code, headers, and sometimes a body.

Anatomy of a request

Example request
GET /users/octocat HTTP/1.1
Host: api.github.com
Accept: application/json
PartExampleMeaning
MethodGETThe kind of operation the client is asking for.
Path/users/octocatThe resource on the server.
HeaderAcceptExtra request metadata, such as preferred response format.
Query string?units=metricNamed values attached to a URL, often used to filter or configure a GET.
BodyJSON documentOptional data sent with a request, often with POST.

GET and POST

GETPOST
Typical purposeRetrieve a resource or information.Submit data for the server to process, often creating something.
Where data goesOften in URL query parameters.Usually in the request body.
Can change server state?It should not be used to make a change.It often creates or changes server-side state.
ExampleFetch a user's public profile.Submit a new comment or task.
IMPORTANT NUANCE

GET is intended to be safe to repeat, but that does not mean every server is perfectly implemented. POST data is not automatically secret just because it is in the body. Use HTTPS for transport security, and never put passwords or API keys in URLs.

Reading status codes

CodeMeaningFirst debugging thought
200 OKRequest succeeded.Inspect the response body.
201 CreatedA resource was created successfully.Look for the new resource or its identifier.
400 Bad RequestRequest was invalid.Check parameters, body, and required fields.
401 UnauthorizedAuthentication is missing or invalid.Check credentials; do not paste secrets into shared code.

STATUS-CODE PATTERN

2xx usually means success, 4xx points to a request or access problem, and 5xx points to a server problem. The response body may contain more specific details.

3 Practice · Make HTTP visible

Hands-on HTTP with curl

curl sends requests from a terminal. The -i option includes response headers and the status line.

Try these against JSONPlaceholder, a practice API intended for demonstrations. Its writes are simulated, so a created item may not persist after the request.

GET one post

Terminal
curl -i https://jsonplaceholder.typicode.com/posts/1

Change /posts/1 to /posts/9999. Compare the status and body. What does the response tell you?

POST a JSON body

Terminal (PowerShell or Bash)
curl -i -X POST https://jsonplaceholder.typicode.com/posts -H "Content-Type: application/json" -d '{"title":"Practice HTTP","userId":1}'

-X POST selects the method, -H adds a header, and -d supplies the body. Look for the response status and returned identifier.

WINDOWS NOTE

On Windows, use curl.exe if PowerShell resolves curl to a different command. If a shell rejects the JSON quoting, adjust the quotes for that shell; the HTTP request itself is the same.

4 Data formats · From response text to Python values

JSON and Web APIs

JSON is a text format; an API is an interface. Many web APIs use JSON, but those ideas are not interchangeable.

You have already used Python's json module to save and load local data. With an API, the JSON text arrives in an HTTP response instead of a file. Python libraries can parse that text into familiar dictionaries, lists, strings, numbers, booleans, and None.

Response JSON
{
  "login": "octocat",
  "public_repos": 8,
  "followers": 18700
}
CONNECT IT TO PYTHON

After parsing, data["login"] is a string and data["public_repos"] is a number. JSON object keys are strings; use brackets or dict.get() to access values.

An API (Application Programming Interface) defines how one program can use another program's capabilities or data. A web API might return JSON, XML, an image, or another format. A regular website often returns HTML for a browser to display; an API endpoint is designed for software clients, but it is not simply "a server that returns JSON."

URLs and query parameters

URL anatomy
https://api.example.com/weather?city=Tbilisi&units=metric
\____________________/ \_____/ \________________________/
       host              path          query parameters

Query parameters are useful for filters, search terms, coordinates, and units. In Python, pass them as a dictionary rather than manually building and escaping the URL.

5 Python · Send requests and parse responses

Using the requests Library

Install the package once, then let it handle URL encoding and JSON conversion.

Terminal
python -m pip install requests

A reliable GET pattern

api_basics.py
import requests

url = "https://api.github.com/users/octocat"

try:
    response = requests.get(url, timeout=10)
    response.raise_for_status()
    data = response.json()
except requests.RequestException as error:
    print(f"Network or HTTP error: {error}")
except ValueError as error:
    print(f"The response was not valid JSON: {error}")
else:
    print(f"Login: {data.get('login', 'unknown')}")
    print(f"Public repositories: {data.get('public_repos', 'unknown')}")

timeout prevents a request from waiting forever. raise_for_status() raises an exception for unsuccessful HTTP responses. .json() parses the response body, but parsing can fail if the server returns invalid JSON or an HTML error page.

Sending JSON with POST

post_example.py
payload = {"title": "Practice HTTP", "userId": 1}
response = requests.post(
    "https://jsonplaceholder.typicode.com/posts",
    json=payload,
    timeout=10,
)
response.raise_for_status()
print(response.status_code)
print(response.json())

The json= argument serializes the dictionary and sets the JSON content type. A real API may require authentication, validation, and a specific response schema.

6 Mini-project · Use a live, key-free API

Live Weather Report

Fetch current conditions from Open-Meteo, parse the response, and display a compact report.

Open-Meteo provides a forecast API that can be used without an API key for non-commercial use. Its API uses coordinates and query parameters. This example requests current temperature and wind speed for Tbilisi.

weather_report.py
import requests

API_URL = "https://api.open-meteo.com/v1/forecast"


def get_weather(city, latitude, longitude):
    params = {
        "latitude": latitude,
        "longitude": longitude,
        "current": "temperature_2m,wind_speed_10m",
        "timezone": "auto",
    }

    try:
        response = requests.get(API_URL, params=params, timeout=10)
        response.raise_for_status()
        payload = response.json()
        current = payload["current"]
        units = payload.get("current_units", {})
        temperature = current["temperature_2m"]
        wind_speed = current["wind_speed_10m"]
    except requests.RequestException as error:
        print(f"Could not contact the weather service: {error}")
        return
    except (ValueError, KeyError, TypeError) as error:
        print(f"The weather response was unexpected: {error}")
        return

    temperature_unit = units.get("temperature_2m", "")
    wind_unit = units.get("wind_speed_10m", "")
    print(f"Current weather for {city}")
    print(f"Temperature: {temperature}{temperature_unit}")
    print(f"Wind speed: {wind_speed}{wind_unit}")


if __name__ == "__main__":
    get_weather("Tbilisi", 41.7151, 44.8271)

What happens in this program?

  1. The coordinates and requested fields are collected in params.
  2. requests encodes those values into the URL and sends a GET request.
  3. The code checks for a failed HTTP response before parsing JSON.
  4. It reads named fields and units, then formats them for a person.
  5. Network failures and unexpected response shapes produce useful messages instead of a traceback.
RUN IT

Save the code as weather_report.py, install requests, and run python weather_report.py. The numeric values change with the live forecast, so your output will differ from someone else's.

7 Applied Practice · Learn by doing

Applied Practice

Use the command line and short Python scripts to inspect real requests, compare responses, and practice debugging deliberately.

Hands-on Practical Application Drills

Drill 1: Explore a REST-style API with curl

Use JSONPlaceholder to make each request. Record the method, path, status code, and one useful field from the response.

  1. GET /users/1; find the user's name and email.
  2. GET /users/1/todos; count the returned items and explain what the nested path means.
  3. GET /users/99999; compare its status and response body with the valid user request.
  4. POST a todo to /todos with a title, completed: false, and userId: 1; note the status and returned ID.

Drill 2: Parse and summarize an API response

Write a short Python script that fetches https://jsonplaceholder.typicode.com/users/1/todos. Print the total item count, then print the titles of incomplete todos only.

  1. Pass a timeout to requests.get() and call raise_for_status().
  2. Parse the response with .json(); it should be a list of dictionaries.
  3. Use a loop and an if not todo["completed"] condition to filter results.
  4. Handle a network or HTTP error so a failed request produces a readable message.

Drill 3: Use query parameters

Fetch posts for a user with GET /posts?userId=1. In Python, pass {"userId": 1} with the params= argument instead of concatenating it into the URL.

Then print how many posts were returned and the first post's title. Try a different user ID and compare the results.

Drill 4: Diagnose a controlled failure

Change the host to a deliberately invalid domain, then change it back and use a nonexistent path. Observe that a connection error and an HTTP 404 are different kinds of failure. Restore the valid URL when finished.

Knowledge check

  1. In a Python script that calls a weather API, which program is the client?
  2. What is the difference between a URL path and a query parameter?
  3. What do the first digits in a 404 and a 503 suggest?
  4. Why should API calls have a timeout?
  5. Why does a successful HTTP status not guarantee that the response contains the JSON fields your program expects?
EXTEND THE PROJECT

Add London or Tokyo as another location. Then let the user choose from a small dictionary of city names and coordinates. Keep the network request in a function, and test invalid choices before calling the API.

8 Homework · Mini CLI projects

Extension Activities for homework

  1. Configuration: Let the user choose Celsius or Fahrenheit where the API supports units, and label every value accurately.
  2. History: Save successful weather lookups to a local JSON file with a timestamp. On startup, add a menu option to view recent searches.
  3. Input validation: Normalize city names, handle blank input, and keep invalid menu selections from triggering requests.
  4. Readable output: Format results as a compact table or report and include the location and observation time.
  5. Testing: Separate formatting and filtering into pure functions, then test them with sample dictionaries without calling the internet.
  6. Documentation: Add a README with setup steps, example commands, API source, known limitations, and one sample run. Do not include secrets.

9 Beyond this lesson · Build on the foundation

API Documentation, Keys, and Bots

Once requests and responses make sense, new APIs become a matter of reading their documentation and following their rules.

API documentation typically explains available endpoints, required parameters, authentication, response fields, rate limits, and error formats. Before writing code, find a small example request and identify what the service expects.

KEEP API KEYS PRIVATE

An API key is a credential, like a password. Do not commit it to source control, publish it in a tutorial, or place it in a URL. For local projects, read it from an environment variable; for deployed applications, use the platform's secret manager. Rotate a key immediately if it is exposed.

Many APIs use GET to retrieve information and POST to submit information. That pattern can power a chat bot, a notification service, or a dashboard. A bot is still a client making requests to a server; webhooks and persistent connections add other communication patterns that can be learned later.

THE COMPLETE MENTAL MODEL

Your program builds a request, sends it to an API endpoint, receives an HTTP response, checks the status, parses the body, and turns the returned data into something useful. That loop is the core of working with web APIs.

From local files to live data

You have followed a request from the client-server model through HTTP, JSON, and Python code. The next API you meet will have different endpoints and fields, but the same habits will serve you: read the docs, inspect the response, handle failure, and keep credentials private.
