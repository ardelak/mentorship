Thinking in Objects (Part 1) — The Blueprint & Attributes

Objective: Understand why procedural variables become messy and learn how to create custom object blueprints using Python class and __init__().

1.1 The Problem: Why Procedural Code Breaks Down

Imagine building an inventory or RPG system using raw variables or loose dictionaries. As soon as you add a second or third item, tracking state quickly turns into spaghetti code:

procedural_mess.py
# Procedural Approach: Loose variables without structural guarantees
player1_name = "Levani"
player1_hp = 100
player1_inventory = ["Potion", "Shield"]

player2_name = "Alexey"
player2_hp = 85
# Oops! We forgot player2_inventory entirely!

def heal(hp, amount):
    return hp + amount

# Easy to pass the wrong parameters or corrupt data state
player1_hp = heal(player1_hp, 20)
THE PROCEDURAL PITFALL

Notice how functions and data are detached. Nothing prevents a programmer from passing negative health, misspelling key names in dictionaries, or missing required properties on new records.

1.2 The Solution: Custom Blueprints with class and __init__()

An Object-Oriented approach couples data (attributes) and actions (methods) together into a single blueprint called a Class. An Instance is an individual object crafted from that blueprint.

book_blueprint.py
class Book:
    # The initializer method runs automatically when creating a new instance
    def __init__(self, title, author, pages):
        # 'self' refers to the specific instance being created right now
        self.title = title
        self.author = author
        self.pages = pages
        self.current_page = 1  # Default starting attribute

# Instantiating two independent objects
book1 = Book("Clean Code", "Robert C. Martin", 464)
book2 = Book("The Pragmatic Programmer", "Andrew Hunt", 352)

# Inspecting instance attributes using dot notation
print(book1.title)        # Output: Clean Code
print(book2.current_page) # Output: 1
DECODING 'SELF' FOR LEVANI

Think of self as a tag saying "MY own personal variable". When book1.title is accessed, Python translates it behind the scenes to Book.title(book1), passing book1 into self!

AHA! MOMENT

Even if you make 1,000 book objects from the same blueprint, changing book1.current_page = 50 will never accidentally corrupt book2's data! They inhabit distinct memory spaces.

1.3 Bonus: Instance Attributes vs. Class Attributes

Everything above (self.title, self.pages) is an instance attribute — unique per object. Python also allows class attributes, defined directly inside the class body, which are shared by every instance unless overridden.

class_vs_instance.py
class Book:
    # CLASS ATTRIBUTE: lives on the Book class itself, shared by every instance
    # unless a specific object overrides it with its own instance attribute.
    library_name = "Levani's Home Library"

    def __init__(self, title, author, pages):
        # INSTANCE ATTRIBUTES: created fresh for every object via 'self'
        self.title = title
        self.author = author
        self.pages = pages

book1 = Book("Clean Code", "Robert C. Martin", 464)
book2 = Book("Dune", "Frank Herbert", 412)

# Both objects read the SAME class attribute — nothing was duplicated
print(book1.library_name)  # Output: Levani's Home Library
print(book2.library_name)  # Output: Levani's Home Library

# Assigning to self.library_name on ONE instance creates a NEW instance
# attribute that shadows the class attribute — it does not change it globally.
book1.library_name = "Levani's School Library"
print(book1.library_name)  # Output: Levani's School Library (shadowed)
print(book2.library_name)  # Output: Levani's Home Library (unchanged)
WHEN TO REACH FOR A CLASS ATTRIBUTE

Use class attributes for genuinely shared, constant-like data (a species name, a tax rate, a default configuration). Use instance attributes for anything that should vary per object — which, in practice, is most of what you'll model.

Thinking in Objects (Part 2) — Methods & Changing State

Objective: Add actions (methods) to classes, modify object state dynamically, and use __str__ for friendly print outputs.

2.1 Defining Instance Methods & Enforcing Rules

Methods are functions defined inside a class that operate directly on the object's instance variables. They enable objects to manipulate their own internal state securely.

smart_bank_account.py
class BankAccount:
    def __init__(self, owner, starting_balance=0.0):
        # Every account object gets its own owner name and balance —
        # changing one account's balance can never touch another's.
        self.owner = owner
        self.balance = starting_balance

    # Instance Method: Deposit funds
    def deposit(self, amount):
        # Guard clause: reject bad input BEFORE it can corrupt self.balance.
        # This is the "protective guard" idea — the object defends its own state.
        if amount <= 0:
            print("❌ Deposit must be positive!")
            return False  # Signal failure so the caller can react
        self.balance += amount  # Mutate THIS object's own state, nothing else's
        print(f"✅ Deposited ${amount:.2f}. New balance: ${self.balance:.2f}")
        return True  # Signal success

    # Instance Method: Withdraw funds safely
    def withdraw(self, amount):
        # Second guard clause: block overdrafts before they ever happen
        if amount > self.balance:
            print(f"⚠️ Insufficient funds! Available: ${self.balance:.2f}")
            return False
        self.balance -= amount
        print(f"💸 Withdrew ${amount:.2f}. Remaining balance: ${self.balance:.2f}")
        return True

2.2 Making Objects Human-Readable with __str__()

If you try printing an object directly with print(account), Python displays an ugly memory reference like <__main__.BankAccount object at 0x7f8c120>. Defining the magic method __str__() solves this instantly!

str_dunder.py
class BankAccount:
    # ... (__init__, deposit, withdraw as above) ...

    def __str__(self):
        # Python calls this AUTOMATICALLY whenever the object needs to become
        # text: print(obj), str(obj), or an f-string like f"{obj}".
        # Must return a string — never print() from inside __str__ itself!
        return f"🏦 Account Owner: {self.owner} | Balance: ${self.balance:,.2f}"

levani_account = BankAccount("Levani", 250.00)
print(levani_account)  # print() calls __str__() behind the scenes
# Output: 🏦 Account Owner: Levani | Balance: $250.00
WHY USE METHODS INSTEAD OF DIRECT ATTRIBUTE ACCESS?

Methods act as protective guards. By using account.withdraw(500), your class validates whether sufficient funds exist before modifying internal state, preventing invalid data states!

Drill 1: The Smart Thermostat Blueprint

Create a class named Thermostat with target temperature attributes and methods to raise/lower temperatures safely within bounds (15°C to 30°C).

drill1_thermostat.py
class Thermostat:
    def __init__(self, room_name, temp=20.0):
        # room_name and temp are instance attributes — every Thermostat
        # object tracks its OWN room and its OWN current temperature.
        self.room_name = room_name
        self.temp = temp

    def set_temperature(self, new_temp):
        # Guard clause keeps self.temp inside a safe, realistic range —
        # this is exactly the same validation pattern as BankAccount.deposit().
        if 15.0 <= new_temp <= 30.0:
            self.temp = new_temp
            print(f"🌡️ {self.room_name} temp set to {self.temp}°C")
        else:
            # Invalid input is rejected; self.temp is left untouched
            print("⚠️ Invalid temperature! Must be between 15°C and 30°C.")

    def __str__(self):
        # Friendly text form used automatically by print(t)
        return f"Thermostat[{self.room_name}]: {self.temp}°C"

# Verification
t = Thermostat("Study Room")
t.set_temperature(22.5)  # Valid — updates self.temp
t.set_temperature(35.0)  # Should trigger warning, self.temp stays at 22.5
print(t)

Drill 2: Student Grade Tracker

Build a Student class that holds a list of grades, provides a method to record new test scores, and calculates the GPA / average dynamically.

drill2_student.py
class Student:
    def __init__(self, name):
        self.name = name
        self.grades = []  # Starts empty — a fresh, independent list per student

    def add_grade(self, score):
        # Validate BEFORE mutating self.grades — never trust raw input
        if 0 <= score <= 100:
            self.grades.append(score)  # Grow this student's own grade list
            print(f"📝 Grade {score} added for {self.name}.")
        else:
            print("❌ Score must be between 0 and 100!")

    def get_average(self):
        # Guard against dividing by zero when no grades exist yet
        if not self.grades:
            return 0.0
        # Computed live from self.grades every time — never stored separately,
        # so it can never drift out of sync with the underlying data.
        return sum(self.grades) / len(self.grades)

    def __str__(self):
        # Calls get_average() each time it's printed, so the summary is always current
        return f"🎓 Student: {self.name} | Average Score: {self.get_average():.1f}%"

# Verification
s = Student("Levani")
s.add_grade(95)
s.add_grade(88)
s.add_grade(100)
print(s)

Mini CLI Project: Task Tracker & Productivity Engine

Combining Object-Oriented Blueprints, Lists of Instances, and Interactive CLI Menus into a Single Runnable Python File.

PROJECT SPECIFICATION

We will construct an object-oriented task manager featuring two primary classes:
1. Task — Object blueprint representing individual tasks, status, and urgency.
2. TaskManager — Manager class handling a collection of Task instances, adding items, toggling completion, filtering, and summary stats.

task_cli_app.py
import sys

class Task:
    """Blueprint for individual task items."""
    def __init__(self, task_id, title, priority="Medium"):
        # Each Task instance stores its own id, title, priority and completion flag.
        self.id = task_id
        self.title = title
        self.priority = priority
        self.is_completed = False  # Every new task starts as NOT done

    def mark_complete(self):
        # A tiny method whose ONLY job is to flip this task's own state.
        # Keeping this logic inside the class (not scattered in main()) is
        # what makes the object "responsible for itself".
        self.is_completed = True

    def __str__(self):
        # Builds the one-line display format used by list_all_tasks() below.
        status = "x" if self.is_completed else " "
        return f"[{status}] #{self.id} | {self.title} ({self.priority} Priority)"


class TaskManager:
    """Manages a list of Task instances and operations."""
    def __init__(self):
        self.tasks = []       # Holds every Task object we've created so far
        self._next_id = 1  # Auto-incrementing ID counter, private by convention (_)

    def add_task(self, title, priority="Medium"):
        # Build a brand-new Task object using the manager's current ID counter...
        new_task = Task(self._next_id, title, priority)
        self.tasks.append(new_task)  # ...then store it in this manager's list
        print(f"✨ Task added: '{title}' with ID #{self._next_id}")
        self._next_id += 1  # Bump the counter so the NEXT task gets a unique ID

    def list_all_tasks(self):
        # Early exit keeps the "happy path" below free of nested if/else clutter
        if not self.tasks:
            print("📭 No tasks currently registered!")
            return
        
        print("\n--- CURRENT TASK LIST ---")
        for task in self.tasks:
            print(task)  # Calls task.__str__() automatically!
        print("-------------------------\n")

    def complete_task(self, task_id):
        # Linear search through self.tasks looking for a matching id.
        for task in self.tasks:
            if task.id == task_id:
                task.mark_complete()  # Delegate the state change to the Task itself
                print(f"🎉 Task #{task_id} marked as completed!")
                return  # Stop as soon as we find and update the match
        # The loop finished without a 'return', so no matching task existed
        print(f"❌ Error: Task #{task_id} not found.")

    def get_stats(self):
        # A generator expression (t.is_completed for t in self.tasks) is
        # summed to count True values, since True behaves like 1 in Python.
        total = len(self.tasks)
        completed = sum(1 for t in self.tasks if t.is_completed)
        pending = total - completed
        print(f"\n📊 STATS: Total: {total} | Completed: {completed} | Pending: {pending}\n")


def main():
    # Interactive Command Line Interface loop
    manager = TaskManager()  # One manager object owns the entire task list
    
    # Pre-populate sample tasks so the menu has something to show immediately
    manager.add_task("Review Python OOP Docs", "High")
    manager.add_task("Commit code to GitHub", "High")

    while True:  # Keep showing the menu until the user chooses to exit
        print("=== LEVANI'S OOP TASK MANAGER ===")
        print("1. View All Tasks")
        print("2. Add New Task")
        print("3. Mark Task Complete")
        print("4. View Summary Stats")
        print("5. Exit")

        choice = input("\nSelect option (1-5): ").strip()

        # The menu logic below never touches manager.tasks directly — it always
        # goes through TaskManager's own methods. That's OOP encapsulation in action.
        if choice == "1":
            manager.list_all_tasks()
        elif choice == "2":
            title = input("Enter task title: ").strip()
            # "or" falls back to "Medium" only if the user just pressed Enter
            prio = input("Enter priority (Low/Medium/High) [Medium]: ").strip() or "Medium"
            if title:
                manager.add_task(title, prio)
            else:
                print("❌ Title cannot be empty!")
        elif choice == "3":
            tid = input("Enter Task ID to complete: ").strip()
            # isdigit() protects int() from crashing on non-numeric input
            if tid.isdigit():
                manager.complete_task(int(tid))
            else:
                print("❌ Please enter a valid numerical ID.")
        elif choice == "4":
            manager.get_stats()
        elif choice == "5":
            print("👋 Happy coding, Levani! Exiting CLI.")
            sys.exit(0)  # Cleanly stops the while-True loop and ends the program
        else:
            # Catches anything that wasn't 1-5, so the loop never crashes on bad input
            print("⚠️ Invalid option. Please enter a number between 1 and 5.")


if __name__ == "__main__":
    main()
