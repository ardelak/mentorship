The Problem with Big Data

Why servers limit your request size and how to respect their rules.

If you ask the NASA Asteroids NeoWs API for a list of all Near-Earth Objects, it has hundreds of thousands of matches. If the API tried to send everything in one JSON file, your computer's RAM would max out, and the API server would likely time out. To solve this, APIs use Pagination.

PAGINATION PATTERNS

APIs typically use one of three methods to chunk data:

  • page & page_size: ?page=2&page_size=20 (Give me page 2, 20 items per page).
  • offset & limit: ?offset=20&limit=20 (Skip the first 20 items, give me the next 20).
  • cursor-based / next_url: The API payload includes a direct "next" URL to call for the next batch. (NASA NeoWs uses this).

Rate Limiting: Code 429

APIs also protect themselves from being spammed. If you request pages too fast in a loop, the server will block you and return an HTTP Status 429 Too Many Requests.

You must look at the response headers (like Retry-After or X-RateLimit-Remaining) to know how long you need to wait before trying again.

2 Part 2 · Engineering Practice (15 min)

Reliable JSON Navigation

Extracting the gold without breaking your script.

The NASA Asteroids NeoWs (Near Earth Object Web Service) API returns data about asteroids passing near Earth. However, the JSON response is heavily nested. The main payload is grouped inside a dictionary called "near_earth_objects". Inside that dictionary, the keys are dynamic date strings (e.g., "2026-10-11"), and the values are lists of asteroids. Each asteroid is itself a dictionary containing further nested dictionaries for "estimated_diameter", "close_approach_data", etc.

Look at this risky code attempting to extract the maximum diameter in meters for the first asteroid on a specific date:

The Risky Chain
# ❌ DANGEROUS: If ANY of these keys are missing, the program crashes!
diameter = data["near_earth_objects"]["2026-10-11"][0]["estimated_diameter"]["meters"]["estimated_diameter_max"]

If there were no asteroids discovered on "2026-10-11", or if the API drops the "meters" key during an update, your program instantly crashes with a KeyError. Let's build a safe parser.

safe_parser.py
def safe_get(dictionary: dict, path: list, default=None):
    """Safely navigate through nested keys without throwing a KeyError."""
    current = dictionary
    # Loop through the list of expected keys
    for key in path:
        # Check if the current item is a dict AND the key exists
        if isinstance(current, dict) and key in current:
            # Move one level deeper
            current = current[key]
        else:
            return default  # The path broke, return default fallback
    return current

# ✅ SAFE: If any key is missing, it just returns 0.0 instead of crashing.
max_diameter = safe_get(asteroid_dict, ["estimated_diameter", "meters", "estimated_diameter_max"], 0.0)

Hands-on Drills

Let's write the code to loop through NASA's pages safely.

Drill 1: Multi-page Crawler

NASA NeoWs provides a links.next URL for the next page of results. We need a while loop to keep fetching data until we hit our page limit or run out of links.

drill1_crawler.py
import os
import requests

all_items = []
api_key = os.getenv("NASA_API_KEY", "DEMO_KEY")
url = f"https://api.nasa.gov/neo/rest/v1/neo/browse?api_key={api_key}"
pages_fetched = 0

# Keep looping as long as we have a URL AND haven't exceeded 3 pages
while url and pages_fetched < 3:
    print(f"Fetching page {pages_fetched + 1}...")
    response = requests.get(url, timeout=10, proxies={"https": ""})
    response.raise_for_status()
    data = response.json()
    
    # Extract the list of objects and add them to our master list
    asteroids = data.get("near_earth_objects", [])
    all_items.extend(asteroids)
    
    # Get the link to the NEXT page (returns None if it doesn't exist)
    # NASA uses data["links"]["next"]
    url = data.get("links", {}).get("next")  # Safe chaining for shallow nesting
    pages_fetched += 1

print(f"Total asteroids collected: {len(all_items)}")

Drill 2: Rate-Limit Defense

If we run the loop above too fast, the API will ban us. We need to pause the script slightly between requests, and gracefully catch a 429 error.

drill2_defense.py
import time
import requests

# Inside your while loop, before fetching the next page:
try:
    response = requests.get(url, timeout=10, proxies={"https": ""})
    response.raise_for_status()
except requests.exceptions.HTTPError as e:
    if response.status_code == 429:
        print("⚠️ 429 Too Many Requests. Stopping early to prevent ban.")
        break  # Exit the loop safely
    else:
        print(f"❌ HTTP Error: {e}")
        break

# Pause execution for half a second before the next loop iteration
time.sleep(0.5)

Project Integration: The Analytics Module

Putting it all together to calculate real statistics.

Now that we have a clean list of dictionaries, we can write an analytics function. This function will filter the data based on user input (e.g., only potentially hazardous asteroids) and output summary statistics.

analytics.py
def print_asteroid_stats(asteroids: list, only_hazardous=False):
    # Filter the list if the user requested only hazardous objects
    if only_hazardous:
        filtered_list = [a for a in asteroids if a["is_hazardous"]]
    else:
        filtered_list = asteroids

    if not filtered_list:
        print("No asteroids matched the criteria.")
        return

    total_found = len(filtered_list)
    
    # Sum all diameters to find the average
    total_diameter = sum(a["max_diameter_m"] for a in filtered_list)
    avg_diameter = total_diameter / total_found
    
    print("\n--- NEO ANALYTICS REPORT ---")
    print(f"Total Objects Found : {total_found}")
    print(f"Average Max Diameter: {avg_diameter:.2f} meters")
    print("----------------------------\n")

if __name__ == "__main__":
    # Simulated Execution with Mock Data
    mock_data = [
        {"name": "433 Eros", "is_hazardous": True, "max_diameter_m": 34000.0},

5 Part 5 · Optimization (10 min)

Local Caching (Speed & Limits)

Don't ask the internet for what you already know.

Local Caching is the technique of temporarily saving expensive data (like a large API response) directly to your local hard drive. Instead of making a network request every time you run your script, the script first checks if a saved version exists and is recent.

Why is Caching Important?

  • Saves API Limits: If an API only allows 1,000 requests per day, caching prevents you from wasting requests while testing your code.
  • Massive Speed Boost: Reading a local JSON file takes milliseconds. Waiting for an API to compile and send paginated data across the internet can take several seconds.
cache_concept.py
import json
import os

# 1. Saving to Cache
with open("nasa_cache.json", "w") as f:
    json.dump(all_items, f)  # Save the heavy list to the hard drive

# 2. Reading from Cache
if os.path.exists("nasa_cache.json"):
    with open("nasa_cache.json", "r") as f:
        cached_data = json.load(f)  # Instant loading! No internet needed.
THE CACHE LIFESPAN

A cache shouldn't live forever. Asteroid data changes daily. In the homework, you will learn how to check the file's "age" using Python's os.path.getmtime() and delete it if it's too old.

1Local Caching

Save the JSON response to a file with a timestamp. If the user runs the script again within 1 hour, load the data from the file instead of making a new network request.

cache_manager.py (Scaffolding)
import json
import os
import time

def load_from_cache(filename="nasa_cache.json", max_age_seconds=3600):
    """Returns cached data if it's less than 1 hour old, else None."""
    if not os.path.exists(filename):
        return None
        
    file_age = time.time() - os.path.getmtime(filename)
    if file_age > max_age_seconds:
        print("Cache expired. Fetching fresh data...")
        return None
        
    print("Loading data from local cache...")
    with open(filename, "r") as f:
        return json.load(f)

def sort_asteroids_by_size(asteroids_list: list):
    """Sorts the list of dictionaries in-place by max_diameter_m descending."""
    # A lambda function extracts the specific key we want to sort by
    asteroids_list.sort(key=lambda x: x["max_diameter_m"], reverse=True)
    return asteroids_list
