1 Part 1 · Concept Basics (15 min)

What a Bot Really Is

A bot is just a program with an API token and a loop.

A Telegram bot is a normal Python program. Telegram's servers hold the chat; your program talks to them over HTTPS. Every message a user sends becomes an Update (a JSON object), and every reply you send is one API call. There is no special bot technology — it is the same requests.get you already know.

TWO WAYS TO RECEIVE MESSAGES
  • Long polling: your program repeatedly asks getUpdates "anything new?". Works on your laptop, no public address needed. We use this.
  • Webhooks: Telegram calls a public URL on your server whenever a message arrives. Better for production hosting.

Getting a token from BotFather

In Telegram, search for @BotFather (the verified one), send /newbot, choose a display name, then a username ending in bot. BotFather replies with a token that looks like 123456789:AAH....

TOKEN = PASSWORD

Anyone holding the token controls your bot. Never paste it into code that goes to GitHub. We will keep it in a .env file. If it leaks, send /revoke to BotFather.

Every Bot API URL has the same shape: https://api.telegram.org/bot<TOKEN>/<METHOD>. Let's test the token with the simplest method, getMe:

step1_getme.py
import os
import requests
from dotenv import load_dotenv

load_dotenv()  # reads BOT_TOKEN from the .env file
TOKEN = os.getenv("BOT_TOKEN")

url = f"https://api.telegram.org/bot{TOKEN}/getMe"
data = requests.get(url, timeout=10).json()

print(data)
# {'ok': True, 'result': {'id': 123456789, 'is_bot': True,
#   'first_name': 'My Helper Bot', 'username': 'my_helper_bot'}}

Every Telegram reply has the same wrapper: "ok" (true/false) and either "result" or "description" (the error). Always check ok first.

2 Part 2 · Engineering Practice (20 min)

A Bot in 20 Lines of Raw HTTP

Before using any library, see what it hides.

First send a message to your bot in Telegram (say "hi"), then fetch it. The response is a list of updates, each with an update_id and a message:

step2_updates.py
updates = requests.get(f"https://api.telegram.org/bot{TOKEN}/getUpdates", timeout=10).json()

# Shape of one update (simplified):
# {"update_id": 501,
#  "message": {"message_id": 7,
#              "from": {"id": 42, "first_name": "Alex"},
#              "chat": {"id": 42, "type": "private"},
#              "text": "hi"}}

for u in updates["result"]:
    print(u["update_id"], u["message"]["text"])
RISKY CHAIN ALERT

Remember Lesson 6? Not every update has "message" — users can edit messages, press buttons, or send photos with no text. u["message"]["text"] would crash. Use your safe_get helper.

Now the full echo bot. The key idea is offset: tell Telegram "I have processed everything up to ID N", so it does not send the same updates again.

step2_echo_raw.py
import os, time
import requests
from dotenv import load_dotenv

load_dotenv()
API = f"https://api.telegram.org/bot{os.getenv('BOT_TOKEN')}"

def safe_get(d, path, default=None):
    for key in path:
        if isinstance(d, dict) and key in d:
            d = d[key]
        else:
            return default
    return d

def send_message(chat_id, text):
    requests.post(f"{API}/sendMessage",
                  json={"chat_id": chat_id, "text": text}, timeout=10)

offset = None  # "next update I want"
print("Bot is running. Press Ctrl+C to stop.")

while True:
    params = {"timeout": 30}          # long polling: server waits up to 30s
    if offset:
        params["offset"] = offset
    data = requests.get(f"{API}/getUpdates", params=params, timeout=40).json()

    for update in data.get("result", []):
        offset = update["update_id"] + 1   # mark as processed
        chat_id = safe_get(update, ["message", "chat", "id"])
        text = safe_get(update, ["message", "text"])
        if chat_id and text:
            send_message(chat_id, f"You said: {text}")
    time.sleep(0.2)

3 Part 3 · Live Practice (30 min)

python-telegram-bot: Handlers

Let the library run the loop; you write only the reactions.

The library does polling, offsets, and JSON parsing for you. You register handlers: "when X happens, run this function". Install it with pip install python-telegram-bot python-dotenv requests.

ASYNC IN ONE SENTENCE

Handler functions are written async def and every Telegram call is prefixed with await. That lets one bot talk to many users at once without blocking. Just follow the pattern for now.

Drill 2: Minimal bot with /start and /help

Every handler receives update (what happened) and context (tools and arguments).

bot_v1.py
import os
from dotenv import load_dotenv
from telegram import Update
from telegram.ext import Application, CommandHandler, ContextTypes

load_dotenv()

async def start(update: Update, context: ContextTypes.DEFAULT_TYPE):
    name = update.effective_user.first_name
    await update.message.reply_text(f"Hi {name}! Send /help to see what I can do.")

async def help_cmd(update: Update, context: ContextTypes.DEFAULT_TYPE):
    await update.message.reply_text("/start - greet\n/help - this list\n/echo [text] - repeat")

async def echo(update: Update, context: ContextTypes.DEFAULT_TYPE):
    # context.args is the list of words after the command
    if not context.args:
        await update.message.reply_text("Usage: /echo hello world")
        return
    await update.message.reply_text(" ".join(context.args))

def main():
    app = Application.builder().token(os.getenv("BOT_TOKEN")).build()
    app.add_handler(CommandHandler("start", start))
    app.add_handler(CommandHandler("help", help_cmd))
    app.add_handler(CommandHandler("echo", echo))
    print("Bot is running...")
    app.run_polling()

if __name__ == "__main__":
    main()

Reacting to plain text

MessageHandler with filters catches non-command text. Handler order matters: the first matching handler wins in its group.

drill3_text_handler.py
from telegram.ext import MessageHandler, filters

async def reply_to_text(update: Update, context: ContextTypes.DEFAULT_TYPE):
    text = update.message.text.lower()
    if "hello" in text or "hi" in text:
        await update.message.reply_text("Hello there! 👋")
    else:
        await update.message.reply_text("I only understand commands. Try /help")

# TEXT = any text message, ~filters.COMMAND = and it is NOT a command
app.add_handler(MessageHandler(filters.TEXT & ~filters.COMMAND, reply_to_text))

Inline keyboards: buttons under a message

Buttons send a callback_data string back to your bot when pressed. You must call query.answer() to stop the button's loading spinner.

drill4_buttons.py
from telegram import InlineKeyboardButton, InlineKeyboardMarkup
from telegram.ext import CallbackQueryHandler

async def menu(update: Update, context: ContextTypes.DEFAULT_TYPE):
    keyboard = [
        [InlineKeyboardButton("🌌 Photo of the day", callback_data="apod"),
         InlineKeyboardButton("☄️ Asteroids", callback_data="neo")],
        [InlineKeyboardButton("❌ Close", callback_data="close")],
    ]
    await update.message.reply_text("Choose:", reply_markup=InlineKeyboardMarkup(keyboard))

async def on_button(update: Update, context: ContextTypes.DEFAULT_TYPE):
    query = update.callback_query
    await query.answer()                      # required!
    if query.data == "close":
        await query.edit_message_text("Menu closed.")
    else:
        await query.edit_message_text(f"You picked: {query.data}")

app.add_handler(CommandHandler("menu", menu))
app.add_handler(CallbackQueryHandler(on_button))

4 Part 4 · Implementation (25 min)

Bot + NASA API: Real Data in Chat

Combine Lesson 6's safe parsing with a live bot.

Now the bot becomes useful: each command calls an external API, safely extracts the useful fields, and formats the answer. Keep API logic in plain functions separate from handlers — you can test them without Telegram.

nasa_service.py
import os
from datetime import date
import requests

KEY = os.getenv("NASA_API_KEY", "DEMO_KEY")

def safe_get(d, path, default=None):
    for key in path:
        if isinstance(d, dict) and key in d:
            d = d[key]
        else:
            return default
    return d

def fetch_apod():
    """Astronomy Picture of the Day -> clean dict, or None on failure."""
    try:
        r = requests.get("https://api.nasa.gov/planetary/apod",
                         params={"api_key": KEY}, timeout=10)
        r.raise_for_status()
    except requests.RequestException:
        return None
    d = r.json()
    return {"title": d.get("title", "Untitled"),
            "url": d.get("url"),
            "type": d.get("media_type", "image"),
            "text": d.get("explanation", "")[:300]}

def fetch_today_asteroids():
    today = date.today().isoformat()
    try:
        r = requests.get("https://api.nasa.gov/neo/rest/v1/feed",
                         params={"start_date": today, "end_date": today, "api_key": KEY},
                         timeout=10)
        r.raise_for_status()
    except requests.RequestException:
        return None
    rocks = safe_get(r.json(), ["near_earth_objects", today], [])
    return [{"name": a.get("name", "?"),
             "hazard": a.get("is_potentially_hazardous_asteroid", False),
             "size": safe_get(a, ["estimated_diameter", "meters", "estimated_diameter_max"], 0.0)}
            for a in rocks]
BLOCKING CALLS

requests is blocking: while it waits for NASA, an async bot freezes for every user. Run it in a worker thread with asyncio.to_thread(...) as shown below.

bot_v2.py (handlers)
import asyncio
from nasa_service import fetch_apod, fetch_today_asteroids

async def apod(update: Update, context: ContextTypes.DEFAULT_TYPE):
    await update.message.reply_text("Contacting NASA... 🛰️")
    data = await asyncio.to_thread(fetch_apod)      # runs requests in a thread

    if data is None:
        await update.message.reply_text("NASA is not responding. Try again later.")
        return
    caption = f"*{data['title']}*\n\n{data['text']}..."
    if data["type"] == "image":
        await update.message.reply_photo(data["url"], caption=caption[:1000],
                                         parse_mode="Markdown")
    else:                                            # APOD can also be a video
        await update.message.reply_text(f"{caption}\n{data['url']}", parse_mode="Markdown")

async def asteroids(update: Update, context: ContextTypes.DEFAULT_TYPE):
    rocks = await asyncio.to_thread(fetch_today_asteroids)
    if rocks is None:
        await update.message.reply_text("Could not reach NASA.")
        return
    if not rocks:
        await update.message.reply_text("No asteroids recorded today.")
        return
    rocks.sort(key=lambda a: a["size"], reverse=True)
    lines = [f"{'⚠️' if a['hazard'] else '✅'} {a['name']} - {a['size']:.0f} m"
             for a in rocks[:5]]
    await update.message.reply_text("Top 5 asteroids today:\n" + "\n".join(lines))

Drill 5: Command with arguments

Let users pick a date: /apod 2024-07-04. Validate the input before calling the API, since users type anything.

drill5_args.py
from datetime import datetime

def parse_date(text):
    try:
        return datetime.strptime(text, "%Y-%m-%d").date().isoformat()
    except ValueError:
        return None

async def apod_date(update: Update, context: ContextTypes.DEFAULT_TYPE):
    if not context.args:
        await update.message.reply_text("Usage: /apod YYYY-MM-DD")
        return
    day = parse_date(context.args[0])
    if day is None:
        await update.message.reply_text("That is not a valid date. Example: 2024-07-04")
        return

Errors, Secrets, and Staying Online

What separates a demo from a bot people can rely on.

hardening.py
import logging, os
from dotenv import load_dotenv

load_dotenv()
logging.basicConfig(format="%(asctime)s | %(levelname)s | %(message)s", level=logging.INFO)
log = logging.getLogger("bot")

TOKEN = os.getenv("BOT_TOKEN")
if not TOKEN:
    raise SystemExit("BOT_TOKEN is missing. Create a .env file (see README).")

async def on_error(update, context):
    # Any exception inside a handler lands here instead of killing the bot
    log.error("Handler failed", exc_info=context.error)
    if update and getattr(update, "effective_message", None):
        await update.effective_message.reply_text("Something went wrong on my side 🛠️")

# in main():  app.add_handler(...)  then:
# app.add_error_handler(on_error)

Rate limits apply to bots too

Telegram allows roughly one message per second per chat. Sending too fast returns HTTP 429 — the same lesson as NASA, with a retry_after value in the response. Do not send long loops of messages; combine lines into one message, as /asteroids does.

WHERE DOES A BOT LIVE?

While your terminal runs, the bot is online; close VS Code and it goes offline. To keep it running 24/7 you deploy it to a server (a small VPS, Railway, Render, or Fly.io). That is a future lesson — today your laptop is the server.
