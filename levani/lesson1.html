Before we dive in: what is VS Code, and why does everyone use it?

Visual Studio Code (almost always just called "VS Code") is a free code editor built by Microsoft. It's not the only one that exists, but it's become the tool of choice for the vast majority of professional developers — which means the habits you build inside it today will transfer directly to real jobs and real projects later.

  • Free and lightweight — it starts up fast and won't bog down an older laptop.
  • Cross-platform — the exact same tool on Windows, Mac, and Linux, so what you learn today works anywhere.
  • Integrated terminal built in — no separate app needed to run commands, which is exactly what we're about to explore.
  • A huge extension marketplace — free add-ons give you instant syntax colouring, autocomplete, and error-checking for Python and almost any other language.
  • Built-in Git support and a debugger — useful once your programs grow past a single file, later in the course.
WHY THIS MATTERS

Every tool we'll use this year — the file explorer, the terminal, running Python files — lives inside this one window. Get comfortable with VS Code once, and every future lesson gets easier.

Installing VS Code

  • Go to code.visualstudio.com in your browser. The site detects your operating system and shows one big Download button.
  • Windows: run the downloaded .exe file, accept the license agreement, and keep the default options checked — especially "Add to PATH". Click Install, then Finish.
  • Mac: open the downloaded .zip file, then drag Visual Studio Code.app into your Applications folder.
  • Linux: download the .deb (Ubuntu/Debian) or .rpm (Fedora/RHEL) package and install it from your terminal, or search "Visual Studio Code" in your distro's software centre.
  • Open VS Code, click the Extensions icon in the left sidebar (it looks like four small squares), search for Python, and install the official Microsoft extension — this is what gives you syntax colours, autocomplete, and the "Run Python File" button.
FIELD NOTE

VS Code is only the editor — it doesn't come with Python itself. Open the integrated terminal and check what you already have installed:

Terminal
$ python --version
Python 3.12.2

If you see a version number, you're ready to go. If you see something like command not found, install Python separately from python.org before our next step — VS Code will find it automatically once it's there.

Welcome & Low-Stress Setup

No pressure, no clock-watching — just a tour of your new workspace.

Open VS Code together and take it slow. There are only three areas that matter today:

  • File Explorer (left sidebar) — every file and folder in your project lives here. Think of it as the table of contents for your work.
  • Code Editor (center) — where you read and write actual code. Each open file gets its own tab along the top.
  • Integrated Terminal (bottom panel, open it with Ctrl + ` on Windows/Linux or Cmd + ` on Mac) — a direct line to your computer, where you'll type commands instead of clicking icons.
TRAIL MARKER

If the terminal panel isn't visible, go to the top menu: View → Terminal. It will always reopen at the bottom of the window.

The "Aha!" moment

Create a file called main.py in your project folder and type exactly this:

main.py 
print("Hello Levani!")

Save the file (Ctrl/Cmd + S — VS Code shows a small dot on the tab if you forget), click into the terminal, and type:

Terminal
$ python main.py
Hello Levani!

That's it. You just told your computer, in its own language, to do something — and it did it. Everything else this course teaches is a variation on that same loop: write → save → run → read the result.

FIELD NOTE

On some machines the command is python3 main.py instead of python main.py. If you see an error like command not found: python, just try python3 — Mac and Linux often keep the "3" to distinguish it from an old, unsupported version of Python.

TROUBLE AHEAD

Nothing happened, or you see SyntaxError? Check for a missing closing parenthesis or quotation mark first — Python is very literal about matching them up in pairs.

Three commands to navigate anywhere, then your first interactive program.

The terminal only ever answers three kinds of questions. Learn these three commands and you can navigate any computer, forever:

Type the first letter or two of a file or folder name, then press Tab. VS Code's terminal will auto-complete it for you — fewer typos, faster navigation.

Building an interactive script together

We'll grow this in three small steps — run it after every single change so you always know exactly which line caused what.

1Store a value in a variable

main.py
name = "Levani"
print(name)

2Ask the user instead of hard-coding it

main.py
name = input("What's your name? ")
print(name)
Terminal
$ python main.py
What's your name? Levani
Levani

3Combine values neatly with an f-string

main.py
name = input("What's your name? ")
age = input("How old are you? ")
print(f"Hello, {name}! In 5 years you'll be {int(age) + 5}.")
Terminal
$ python main.py
What's your name? Levani
How old are you? 17
Hello, Levani! In 5 years you'll be 22.
FIELD NOTE

The letter f right before the opening quote turns a normal string into an f-string — anything inside { } gets calculated and inserted automatically. Forget the f, and Python will print the curly braces literally instead of the value.

TROUBLE AHEAD — two classics

TypeError: can only concatenate str (not "int") to str — happens if you try "Age: " + age directly. input() always returns text, even for numbers, so wrap it in int(age) first if you need to do math.

NameError: name 'nane' is not defined — a simple typo. Python variable names must match exactly, every time, including capitalisation.

Introducing the Starter Template Workflow

This is exactly how every homework file from now on will work.

From today onward, homework arrives as a "scaffolded" folder — a project that's already half-built, with clear notes on what's left for you to add. Here's what that folder looks like on disk:

File Explorer view
lesson1-homework/
├── profile_builder.py   # the file you'll edit
└── README.md             # task instructions

Open profile_builder.py and you'll see comments like this scattered through it:

profile_builder.py
# TODO: Ask the user for their name and store it in a variable called `name`

A # TODO comment is a note left just for you — Python ignores everything after a #, so it never affects the program, but VS Code often highlights these lines so they're easy to spot. Your job is simply to replace the "gap" with real code, one TODO at a time.

TRAIL MARKER

Run the script after finishing each TODO, not just at the very end. If something breaks, you'll instantly know it was caused by the line you just added — not by hunting through fifteen lines of new code.

WHY THIS MATTERS

Reading someone else's scaffolded code and filling in the gaps is precisely what real junior-developer work looks like — nobody starts from a totally blank file. Getting comfortable with TODOs now is a genuine head start.

SCAFFOLDED HOMEWORK · 1–1.5 HOURS

Profile Generator Script

profile_builder.py  ·  estimated time: 60–90 minutes

Your mission: turn three simple questions into a stylish terminal profile badge — a framed little card, printed entirely out of text, that shows off who you are.

profile_builder.py (starter file)
# profile_builder.py
# Your mission: turn three simple questions into a stylish terminal "profile badge".

# TODO 1: Ask for the user's name and store it in a variable called `name`


# TODO 2: Ask for their favorite programming language and store it in `language`


# TODO 3: Ask for their favorite hobby and store it in `hobby`


# TODO 4: Use f-strings to print a neatly framed profile badge
#         using name, language, and hobby.

1Collect the three answers

Replace TODOs 1–3 with three input() calls, exactly the way we practiced in Waypoint 2. Give each question a friendly prompt — the text inside the parentheses is what Levani-from-the-future will actually read when running the script.

TRAIL MARKER

Test after finishing this step alone — even before touching the badge. If the script asks three sensible questions and prints nothing fancy yet, you're exactly on schedule.

2Build the profile badge

Now use f-strings (one or several print() calls) to turn those three variables into something that looks like a badge, not just three lines of plain text. Here's the target output:

╔══════════════════════════════╗ ║ PROFILE BADGE ║ ╠══════════════════════════════╣ ║ Name: Levani ║ ║ Language: Python ║ ║ Hobby: Chess ║ ╚══════════════════════════════╝

A few different ways to get there — pick whichever feels most comfortable:

  • Simplest: hard-code a border out of repeated characters, e.g. "=" * 32, printed above and below your three lines.
  • Neater: paste box-drawing characters straight into your string — ║, ═, ╔, ╗, ╚, ╝, ╠, ╣ — and lay them out by hand.
  • Extra polish: use an f-string alignment spec like f"{name:<10}" to left-pad a value to a fixed width, so every row lines up perfectly regardless of how long the answer is.
profile_builder.py (one possible finish)
print("╔══════════════════════════════╗")
print(f"║ Name:      {name:<18}║")
print(f"║ Language:  {language:<18}║")
print(f"║ Hobby:     {hobby:<18}║")
print("╚══════════════════════════════╝")
FIELD NOTE

Don't chase pixel-perfect alignment before the badge even works. Get the three values printing correctly first, then spend your remaining time making it pretty — that order saves the most frustration.

Self-check checklist

🧯 FRUSTRATION CIRCUIT-BREAKER

Seeing a File Not Found error when you try to run the script? Almost always one of these three things:

1. You're not cd'd into the folder that actually contains profile_builder.py — run pwd then ls to double-check.
2. The filename is spelled slightly differently than you typed (check for underscores vs. dashes, and correct capitalisation).
3. You typed python when your machine needs python3 (or vice versa).

Stuck for more than five minutes? Stop, don't spiral — just send a screenshot of the exact error in chat. That's what it's there for.
