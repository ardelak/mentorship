Giving Objects Memory (Part 1) — Persistence with JSON

Objective: Understand why in-memory data disappears when a program ends, and learn to serialize/deserialize objects to and from disk using Python's json module.

1.1 The Problem: Programs Forget Everything

When task_cli_app.py is running, every Task object lives in RAM (memory). The moment the program exits — even by choosing option 5 politely — that memory is wiped clean. Run the program again tomorrow, and manager.tasks starts as an empty list all over again.

THE MEMORY PITFALL

Objects are not automatically remembered between separate runs of a program. To survive, their data must be written somewhere permanent — a file on disk, a database, etc. — and read back in on the next run.

1.2 Two-Way Translation: Objects ↔ JSON Text

JSON (JavaScript Object Notation) is a plain-text format that looks almost identical to a Python dictionary. It's the standard way to save structured data to a file. But a Task object itself can't be dumped straight into JSON — we first need to encode it into a plain dict, and later decode a dict back into a real Task object.

task_persistence_basics.py
import json

class Task:
    def __init__(self, task_id, title, priority="Medium", is_completed=False):
        self.id = task_id
        self.title = title
        self.priority = priority
        self.is_completed = is_completed

    def to_dict(self):
        # ENCODE: turn this object's attributes into a plain, JSON-friendly dict
        return {
            "id": self.id,
            "title": self.title,
            "priority": self.priority,
            "is_completed": self.is_completed
        }

    @classmethod
    def from_dict(cls, data):
        # DECODE: rebuild a brand-new Task object from a plain dict
        return cls(data["id"], data["title"], data["priority"], data["is_completed"])


task = Task(1, "Learn JSON", "High")
print(json.dumps(task.to_dict(), indent=2))
# Output:
# {
#   "id": 1,
#   "title": "Learn JSON",
#   "priority": "High",
#   "is_completed": false
# }
DECODING @classmethod

@classmethod marks from_dict as belonging to the class itself, not one existing object — that's why it receives cls instead of self. It's used as an alternative constructor: instead of Task(1, "Learn JSON", ...), you can build a Task straight from a dictionary with Task.from_dict(some_dict).

1.3 Saving & Loading a Whole List of Tasks

A real Task Tracker doesn't just save one task — it needs to save (and later restore) the entire self.tasks list on TaskManager. The pattern is the same, just wrapped in a loop.

task_manager_persistence.py
import json

class TaskManager:
    def __init__(self):
        self.tasks = []
        self._next_id = 1

    # ... add_task, list_all_tasks, complete_task as before ...

    def save_to_file(self, filename="tasks.json"):
        # Turn every Task object into a dict, then write the whole list as JSON
        data = [task.to_dict() for task in self.tasks]
        with open(filename, "w") as f:
            # 'with' guarantees the file is closed automatically, even on error
            json.dump(data, f, indent=2)
        print(f"💾 Saved {len(self.tasks)} tasks to {filename}")

    def load_from_file(self, filename="tasks.json"):
        try:
            with open(filename, "r") as f:
                data = json.load(f)
            # Rebuild real Task objects from the loaded dicts
            self.tasks = [Task.from_dict(item) for item in data]
            # Keep the ID counter ahead of every loaded task, so future new tasks
            # never collide with an ID that already exists on disk
            self._next_id = max((t.id for t in self.tasks), default=0) + 1
            print(f"📂 Loaded {len(self.tasks)} tasks from {filename}")
        except FileNotFoundError:
            # First-ever run: there's no file yet, so just start with an empty list
            print(f"ℹ️ No saved file found at {filename} — starting fresh.")
WHY try / except HERE?

open(filename, "r") crashes the whole program with a FileNotFoundError if the file doesn't exist yet — which is exactly what happens the very first time the app runs. Wrapping it in try/except lets us handle that expected situation gracefully instead of crashing.

AHA! MOMENT

Notice save_to_file and load_from_file live on TaskManager, not scattered in main(). The manager is responsible for its own persistence — the CLI menu just calls the method and trusts it to work.

Extending Blueprints (Part 2) — Inheritance & super()

Objective: Learn how one class can reuse another class's code through inheritance, using class Child(Parent): and super().

2.1 The Problem: Copy-Pasting Classes

Imagine you want an UrgentTask that's always High priority and prints with a 🔥. The tempting-but-wrong approach is to copy the entire Task class and rename it:

copy_paste_mistake.py
class UrgentTask:
    # ❌ Every line here is duplicated from Task — if we ever fix a bug
    # in Task, we now have to remember to fix it here too!
    def __init__(self, task_id, title):
        self.id = task_id
        self.title = title
        self.priority = "High"
        self.is_completed = False

    def mark_complete(self):
        self.is_completed = True
THE DUPLICATION TRAP

Copy-pasted code drifts apart over time. Fix a bug in one copy and forget the other, and now the two classes silently disagree about how a "task" should behave.

2.2 The Solution: class UrgentTask(Task):

Inheritance lets a child class automatically reuse everything a parent class already defines, and only write the parts that are genuinely different.

urgent_task_inheritance.py
class Task:
    def __init__(self, task_id, title, priority="Medium"):
        self.id = task_id
        self.title = title
        self.priority = priority
        self.is_completed = False

    def mark_complete(self):
        self.is_completed = True

    def __str__(self):
        status = "x" if self.is_completed else " "
        return f"[{status}] #{self.id} | {self.title} ({self.priority} Priority)"


class UrgentTask(Task):  # (Task) means "UrgentTask IS a Task, plus extras"
    def __init__(self, task_id, title):
        # super() hands off to Task's own __init__, so we never repeat that
        # logic — we just always lock priority to "High" for UrgentTasks.
        super().__init__(task_id, title, priority="High")

    def __str__(self):
        # OVERRIDE: reuse Task's own __str__ output via super(), then decorate it
        base_text = super().__str__()
        return f"🔥 {base_text}"


t1 = Task(1, "Read chapter 4")
u1 = UrgentTask(2, "Submit assignment")

print(t1)  # [ ] #1 | Read chapter 4 (Medium Priority)
print(u1)  # 🔥 [ ] #2 | Submit assignment (High Priority)

# UrgentTask gets mark_complete() for FREE — it was never redefined here!
u1.mark_complete()
print(u1)  # 🔥 [x] #2 | Submit assignment (High Priority)
DECODING super()

Think of super() as saying "first, go do whatever my parent class already does". Inside UrgentTask.__init__, super().__init__(...) literally runs Task.__init__ on this same object — filling in id, title, priority, and is_completed — before UrgentTask adds anything of its own.

AHA! MOMENT

UrgentTask never defines mark_complete() — yet u1.mark_complete() still works perfectly. That's inheritance: every method on Task is automatically available on UrgentTask unless UrgentTask chooses to override it.

3.1 Drill: Contact Book Persistence

A small address book that saves itself to contacts.json and can reload every contact back into real Contact objects.

drill1_contacts.py
import json

class Contact:
    def __init__(self, name, phone):
        self.name = name
        self.phone = phone

    def to_dict(self):
        return {"name": self.name, "phone": self.phone}

    @classmethod
    def from_dict(cls, data):
        return cls(data["name"], data["phone"])


def save_contacts(contacts, filename="contacts.json"):
    data = [c.to_dict() for c in contacts]
    with open(filename, "w") as f:
        json.dump(data, f, indent=2)
    print(f"💾 Saved {len(contacts)} contacts.")

def load_contacts(filename="contacts.json"):
    with open(filename, "r") as f:
        data = json.load(f)
    return [Contact.from_dict(item) for item in data]


# Verification
book = [Contact("Levani", "+995 555 12 34 56"), Contact("Nina", "+995 555 98 76 54")]
save_contacts(book)

reloaded = load_contacts()  # A brand-new list of real Contact objects
for c in reloaded:
    print(f"{c.name}: {c.phone}")

3.2 Drill: Vehicle → Car Inheritance

A parent Vehicle class with shared behavior, and a child Car that adds one attribute and one method of its own.

drill2_vehicle_car.py
class Vehicle:
    def __init__(self, make, model):
        self.make = make
        self.model = model
        self.speed = 0

    def accelerate(self, amount):
        self.speed += amount

    def __str__(self):
        return f"{self.make} {self.model} — {self.speed} km/h"


class Car(Vehicle):
    def __init__(self, make, model, trunk_capacity):
        super().__init__(make, model)  # Vehicle sets make, model, speed for us
        self.trunk_capacity = trunk_capacity  # Car adds ONE new attribute

    def load_trunk(self, liters):
        if liters <= self.trunk_capacity:
            print(f"🧳 Loaded {liters}L into the trunk.")
        else:
            print(f"❌ Trunk only holds {self.trunk_capacity}L!")


# Verification
my_car = Car("Toyota", "Corolla", 470)
my_car.accelerate(60)   # Inherited from Vehicle — Car never redefined this
my_car.load_trunk(300)  # Defined only in Car
print(my_car)          # __str__ also inherited from Vehicle

Mini-Project: Upgrading the Task Tracker

Objective: combine persistence and inheritance inside the very same Task Tracker CLI from last lesson.

We're upgrading task_cli_app.py in three ways: (1) Task can now convert itself to/from a dict, (2) TaskManager auto-loads saved tasks on startup and auto-saves on exit, and (3) a new UrgentTask class is available from the menu.

task_cli_app_v2.py
import sys
import json

class Task:
    """Blueprint for individual task items."""
    def __init__(self, task_id, title, priority="Medium", is_completed=False):
        self.id = task_id
        self.title = title
        self.priority = priority
        self.is_completed = is_completed  # NEW: can now be restored as already-done

    def mark_complete(self):
        self.is_completed = True

    def to_dict(self):
        # NEW: converts this object into a JSON-friendly dict
        return {"id": self.id, "title": self.title,
                "priority": self.priority, "is_completed": self.is_completed}

    @classmethod
    def from_dict(cls, data):
        # NEW: rebuilds a Task (or UrgentTask, via cls!) from a saved dict
        return cls(data["id"], data["title"], data["priority"], data["is_completed"])

    def __str__(self):
        status = "x" if self.is_completed else " "
        return f"[{status}] #{self.id} | {self.title} ({self.priority} Priority)"


class UrgentTask(Task):
    """NEW: A Task that is always High priority and prints with a 🔥."""
    def __init__(self, task_id, title, is_completed=False):
        super().__init__(task_id, title, priority="High", is_completed=is_completed)

    def __str__(self):
        return f"🔥 {super().__str__()}"


class TaskManager:
    """Manages a list of Task/UrgentTask instances plus persistence."""
    def __init__(self):
        self.tasks = []
        self._next_id = 1

    def add_task(self, title, priority="Medium", urgent=False):
        # Build either a plain Task or an UrgentTask — same list, two blueprints
        if urgent:
            new_task = UrgentTask(self._next_id, title)
        else:
            new_task = Task(self._next_id, title, priority)
        self.tasks.append(new_task)
        print(f"✨ Task added: '{title}' with ID #{self._next_id}")
        self._next_id += 1

    def list_all_tasks(self):
        if not self.tasks:
            print("📭 No tasks currently registered!")
            return
        print("\n--- CURRENT TASK LIST ---")
        for task in self.tasks:
            print(task)  # Calls the right __str__ automatically — Task's or UrgentTask's
        print("-------------------------\n")

    def complete_task(self, task_id):
        for task in self.tasks:
            if task.id == task_id:
                task.mark_complete()
                print(f"🎉 Task #{task_id} marked as completed!")
                return
        print(f"❌ Error: Task #{task_id} not found.")

    def save_to_file(self, filename="tasks.json"):
        data = [task.to_dict() for task in self.tasks]
        with open(filename, "w") as f:
            json.dump(data, f, indent=2)
        print(f"💾 Saved {len(self.tasks)} tasks to {filename}")

    def load_from_file(self, filename="tasks.json"):
        try:
            with open(filename, "r") as f:
                data = json.load(f)
            # Reconstruct UrgentTask when priority was "High" AND it was saved that
            # way, otherwise a plain Task — keeps loaded objects the right type
            self.tasks = []
            for item in data:
                if item["priority"] == "High":
                    self.tasks.append(UrgentTask(item["id"], item["title"], item["is_completed"]))
                else:
                    self.tasks.append(Task.from_dict(item))
            self._next_id = max((t.id for t in self.tasks), default=0) + 1
            print(f"📂 Loaded {len(self.tasks)} tasks from {filename}")
        except FileNotFoundError:
            print(f"ℹ️ No saved file found at {filename} — starting fresh.")

    def get_stats(self):
        total = len(self.tasks)
        completed = sum(1 for t in self.tasks if t.is_completed)
        print(f"\n📊 STATS: Total: {total} | Completed: {completed} | Pending: {total - completed}\n")


def main():
    manager = TaskManager()
    manager.load_from_file()  # NEW: restore last session's tasks automatically

    while True:
        print("=== LEVANI'S OOP TASK MANAGER (v2) ===")
        print("1. View All Tasks")
        print("2. Add New Task")
        print("3. Add URGENT Task")  # NEW menu option
        print("4. Mark Task Complete")
        print("5. View Summary Stats")
        print("6. Save & Exit")  # NEW: exit now saves first

        choice = input("\nSelect option (1-6): ").strip()

        if choice == "1":
            manager.list_all_tasks()
        elif choice == "2":
            title = input("Enter task title: ").strip()
            prio = input("Enter priority (Low/Medium/High) [Medium]: ").strip() or "Medium"
            if title:
                manager.add_task(title, prio)
            else:
                print("❌ Title cannot be empty!")
        elif choice == "3":
            title = input("Enter urgent task title: ").strip()
            if title:
                manager.add_task(title, urgent=True)  # priority is forced "High" inside UrgentTask
            else:
                print("❌ Title cannot be empty!")
        elif choice == "4":
            tid = input("Enter Task ID to complete: ").strip()
            if tid.isdigit():
                manager.complete_task(int(tid))
            else:
                print("❌ Please enter a valid numerical ID.")
        elif choice == "5":
            manager.get_stats()
        elif choice == "6":
            manager.save_to_file()  # NEW: persist before exiting
            print("👋 Saved! Happy coding, Levani.")
            sys.exit(0)
        else:
            print("⚠️ Invalid option. Please enter a number between 1 and 6.")


if __name__ == "__main__":
    main()

🟡 Challenge 2: A Debugging-Friendly __repr__

HINT

Python calls __repr__ automatically when you type an object's name alone at the interactive prompt, or when an object sits inside a list that gets printed. A common pattern is return f"Task({self.id!r}, {self.title!r}, {self.priority!r})".
