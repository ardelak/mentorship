Architectural Refactoring: From Monolith to Packages

Solving the “everything in one file” trap with Separation of Concerns.

Past about 200 lines, a monolithic main.py causes three problems:

  • Untestable logic: input(), requests.get() and parsing in one function means you cannot test the parser without the network.
  • Fragile changes: reformatting a Telegram message can break the NASA pagination loop.
  • Merge conflicts: one giant file guarantees constant Git conflicts in a team.

The fix is a Python package tracker/. Any folder with an __init__.py is importable:

Simulating Code Review with a Pull Request

After pushing, open the repository and click “Compare & pull request”:

  1. Title & summary: a clear title and a 3-bullet summary of what changed.
  2. Line-by-line review: your mentor comments on the diff, e.g. “Use the default .env filename in load_dotenv() so cloud deployment works automatically.”
  3. Follow-up commits: edit locally, run git commit -am "fix: standardize .env filename" and git push. The open PR updates automatically.
  4. Merge & clean up: click “Merge pull request”, then git checkout main && git pull.

Automated Unit Testing with unittest.mock

How do you test an API & Telegram bot with no Wi-Fi, or with zero API quota left?

If tests called NASA and Telegram for real, 50 runs a day would: burn your hourly quota, spam your phone with fake alerts, and become flaky whenever Wi-Fi drops, even though your code is correct.

CONCEPT: MOCKINGA Mock is a simulated object that stands in for a real service (requests.get, requests.post). With unittest.mock.patch we intercept the call in memory and return a pre-programmed answer.

How @patch Works

@patch("tracker.client.requests.Session.get") temporarily swaps get for a controllable MagicMock and passes it to your test as mock_get:

  • mock_get.return_value.status_code = 200: simulates HTTP 200 OK.
  • mock_get.return_value.json.return_value = {...}: what response.json() returns.
  • mock_get.assert_called_once(): proves the HTTP call was attempted exactly once.
PATCH WHERE IT IS USEDPoint @patch() at the module that uses the function ("tracker.notifier.requests.post"), not just "requests.post".

Bridge to Block 3: Where JSON Caching Hurts

  • Complex queries: “hazardous asteroids over 200 m from the last 30 days, sorted by miss distance” means loading and looping through everything by hand.
  • Slow search: the whole file is read into memory for every lookup.
  • Fragile writes: two processes writing at once, or a crash mid-write, can corrupt cache.json.
REMEMBERRelational tables, SQL queries and SQLite solve exactly these limits. That is Block 3.
